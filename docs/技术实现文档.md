# 野兔 v2 · 技术实现文档

> 版本 2.0.0 · PyQt6 6.11 + PyInstaller 6.22 · 目标产物 `dist/野兔v2.app`(macOS)
> 界面样式参考 TCode GUI(深色开发者工具风格) · 前代 v1(Tkinter)位于 `../yetu`

---

## 一、总体架构

```
main.py                        入口(四种模式,见 §5)
野兔v2.spec                    PyInstaller 配置
build.sh                       打包脚本(打包 + frozen 冒烟)
yetu/
├── __init__.py                __version__ / APP_NAME
├── qrterm.py                  零依赖二维码(编码 + 渲染)
├── core/                      核心层(无 Qt 依赖,可独立测试)
│   ├── env.py                 内置工具定位
│   ├── adb.py                 Adb / Hdc 连接器
│   ├── device.py              设备抽象(信息/应用/网络/代理)
│   ├── assistant.py           代理配置助手 HTTP 服务
│   └── assistant_page.html    助手手机页面(单文件,零外部资源)
└── gui/                       界面层(PyQt6)
    ├── theme.py               深色 QSS + 配色常量
    ├── workers.py             Worker(QThread)
    ├── widgets.py             表格 / 徽标 / 等宽字体
    ├── main_window.py         主窗口
    └── panels/                六个功能面板
        ├── base.py            PanelBase(run_async 统一后台执行)
        ├── device_panel.py    手机信息
        ├── apps_panel.py      已装应用
        ├── network_panel.py   网络信息
        ├── proxy_panel.py     全局代理
        ├── install_panel.py   安装应用
        └── assistant_panel.py 配置助手
```

分层原则:**core 不 import Qt** —— adb/hdc/助手服务全部可在无界面环境
(`--selftest` / `--smoke` / CI)直接验证;gui 只做"调用 core + 渲染"。

## 二、核心模块实现

### 2.1 内置工具定位(`core/env.py`)

`find_tool(name)` 按优先级返回 adb/hdc 可执行路径,保证**用户机器零环境依赖**:

1. 环境变量 `YETU_TOOLS/<subdir>/<name>`(调试覆盖用)
2. 打包态(`sys.frozen`):`Contents/MacOS`、`Contents/Resources`、`sys._MEIPASS`、`_internal` 下的 `tools/` 或直接 `<subdir>/`
3. 开发态:项目根 `tools/<subdir>/<name>`
4. 系统 `PATH` 兜底(`shutil.which`)

PyInstaller 打包时 `datas=[("tools","tools"), ("yetu/core/assistant_page.html","yetu/core")]`,
macOS onedir 产物实际落盘于 `Contents/Frameworks/`,PyInstaller 自动建
`Contents/Resources/tools → ../Frameworks/tools` 软链,上述候选路径均可命中。

### 2.2 连接器层(`core/adb.py`)

`Adb` 与 `Hdc`(`Hdc(Adb)` 继承,仅覆写有差异的方法)对外提供**同一套接口**,
adb/hdc 命令差异全部收敛在这一层:

| 方法 | adb 实现 | hdc 实现 |
|---|---|---|
| `devices()` | `adb devices -l`(解析 model/status,过滤 offline) | `hdc list targets`(过滤 `[Empty]`) |
| `shell()` | `adb -s <serial> shell` | `hdc -t <serial> shell` |
| `get_prop()` | `getprop <key>` | `param get <key>` |
| `list_packages()` | `pm list packages -3` | `bm list -p` |
| `package_version()` | `dumpsys package`(取 versionName) | `bm dump -n` |
| `get/set/clear_proxy()` | `settings put/delete global http_proxy` | 同(双保险 `:0` + delete) |
| `install()` | `adb install -r -t`(流式逐行回调) | `hdc install`(流式) |

`list_all_devices()` 同时跑两连接器,按 `(serial, transport)` 去重 ——
同一台鸿蒙手机可能同时出现在 adb 与 hdc 中,界面分别标「安卓/鸿蒙」。
`install()` 用 `subprocess.Popen` 逐行读 stdout,回调驱动 UI 流式显示。

子进程统一 `encoding="utf-8", errors="replace"`,避免 Windows/越狱 ROM 的脏字节崩进程。

### 2.3 设备抽象(`core/device.py`)

`Device(serial, transport, model)` dataclass;`label` 属性生成
`<serial> [安卓|鸿蒙](<model>)` 供下拉框显示。功能函数:

- `get_device_info()`:属性键映射表 `(标签, adb键, hdc键)`
  (如 `ro.product.model` ↔ `const.product.model`)+ `wm size/density` + 电池;
  单项失败显示 `—`,不让一个失败拖垮整页
- `list_apps()`:`pm/bm` 列包;版本号逐包 `dumpsys` 较慢,**前 60 个查版本**其余显示 `—`
- `get_network_text()`:`ip addr` + DNS/代理属性 + WiFi 状态拼装为分段文本

### 2.4 代理配置助手(`core/assistant.py`)

`ProxyAssistant`:标准库 `http.server.ThreadingHTTPServer` 跑守护线程,
一个实例一个端口,状态全部实例化(与 GUI 解耦,可多开):

- `GET /proxy`:手机配置页。服务端按 `User-Agent` 分流
  (`iphone/ipad → iOS 步骤`,`android → Android 步骤`,其余给双份供电脑预览);
  占位符替换顺序为**先插步骤片段再统一替换地址** —— 步骤片段内部含
  `__HOST__/__PORT__` 字面量,顺序颠倒会残留占位符(开发中实际踩过的坑)
- `GET /api/status`:`{"listening": bool, "host": ..., "port": ...}`
  探测电脑抓包端口(默认 8888)是否有服务监听。**双次连接确认**:
  连续两次 `create_connection` 都成功才判定在线 —— 监听刚关闭时内核
  accept 队列的残留连接会让端口短暂还能握手,第二次连接即被拒绝;
  真实抓包服务(Charles/mitmproxy)则持续接受连接
- 页面(`assistant_page.html`):深色卡片式单页,零外部资源(局域网秒开、断外网可用);
  复制按钮优先 `navigator.clipboard`(仅 HTTPS),**http 下回退
  `textarea + document.execCommand('copy')`**;状态徽标 `fetch('/api/status')` 5 秒轮询

线程边界:服务回调(`on_log`/`on_chat` 类)发生在服务子线程,
GUI 侧经 `pyqtSignal` 桥(队列化)回主线程,严禁跨线程直写控件。

### 2.5 二维码(`qrterm.py`)

纯标准库 QR 编码器(无任何第三方依赖):

- 字节模式,版本 1–10 自动选最小可容纳版本,纠错级别 M
- Reed-Solomon EC(GF(256),本原多项式 0x11D),多块数据/EC 列交织
- 掩码 0–7 全评估(罚分规则 1+2),格式信息 BCH(15,5)+0x5412 掩码,
  v7+ 版本信息块正确预留(两处 3×6);对齐图案**只跳过与三个定位图案
  重合的角部组合**,与时序线重合的必须绘制(其明暗与时序天然一致)
- 正确性经 zxing-cpp 解码回归:**全版本 × 满容量/半容量/最短全部可解码,
  V7/V10 与官方 qrcode 库 8 种掩码逐格一致**
- 渲染:GUI 内画成 `QImage→QPixmap`(白底黑码);终端为 ANSI 半块「▀」
  (非 TTY 自动退化 ASCII)

## 三、GUI 层实现

### 3.1 主窗口(`gui/main_window.py`)

```
┌ header    品牌「🐇 野兔」+ 副标题 + 版本            QFrame#header
├ devbar    设备下拉 + ↻刷新设备(F5) + adb✓/hdc✓ 状态   QFrame#devbar
├ tabs      六个功能面板                            QTabWidget
├ log dock  命令日志(时间戳 + $ 命令 + ⏎ 结果)      QDockWidget(可关)
└ statusbar 设备状态消息 + ⏳ 忙碌指示               QStatusBar
```

- 设备刷新:Worker 跑 `list_all_devices`,**保留当前选择**(serial+transport 匹配),
  无设备时状态栏红色提示;刷新期间按钮禁用防重入
- 切换 Tab 自动刷新当前面板(有设备时);`closeEvent` 遍历面板回收后台服务(助手)

### 3.2 主题(`gui/theme.py`)

全局 QSS(参考 TCode GUI):底色 `#171a1f`、卡片 `#1b1f26`、边框 `#2a2f38`、
主色 `#2e70ef`(主按钮/选中 Tab 下划线/表格选中)、语义色
`#4ade80`(绿)/`#f87171`(红)/`#fbbf24`(黄)。状态徽标用 objectName 切换
(`chipOk/chipWarn/chipErr/chipDim`),切换后需 `unpolish+polish` 重刷样式。
另修了 `QMainWindow::separator`(dock 分隔条)原生拖拽圆点与深色主题的违和。

### 3.3 线程模型

| 场景 | 机制 |
|---|---|
| adb/hdc 命令、文件列表、删除 | `Worker(QThread)`,`done=pyqtSignal(object)`,结果或异常实例回主线程 |
| APK/HAP 安装 | `InstallWorker(QThread)`,`line=pyqtSignal(str)` 逐行回传,流式写日志框 |
| 面板通用封装 | `PanelBase.run_async(fn, on_done, busy_btn, busy_text, cmd)`:执行期禁用按钮(结束还原文字,杜绝「永远加载中」)、状态栏 ⏳ 计数、操作写命令日志、异常统一红字提示 |
| 助手服务回调 | 面板级 `pyqtSignal` 桥(子线程 emit → 队列 → 主线程写日志) |
| 助手/设备启动结果 | 服务线程置位 `threading.Event`,主线程 `QTimer` 80ms 轮询(替代 sleep 竞态) |

原则:**Qt 控件只在主线程碰**;所有阻塞操作(子进程/网络/磁盘)进后台线程。

### 3.4 面板注册

`panels/__init__.py::PANELS` 显式列表,主窗口按序生成 Tab。
新面板 = 继承 `PanelBase`(`_build/_refresh/on_device_changed`) + 加入列表。

## 四、打包(`野兔v2.spec` / `build.sh`)

- 入口 `main.py`;`windowed`(无控制台);macOS BUNDLE(`野兔v2.app`,
  `com.yetu.toolbox.v2`,adhoc 签名);Windows 分支为 onefile exe(同 spec)
- `datas`:① `tools/`(adb/hdc + `libusb_shared.dylib`)② 助手手机页面
  (`yetu/core/assistant_page.html`,运行时按包内路径读取)
- 依赖:PyQt6 ≥6.6、pyinstaller ≥6.0;**spec 顶部有依赖快速失败守卫**
  (缺 PyQt6 时直接报错并给安装指引,而不是产出必坏的 exe)
- `build.sh`:PyInstaller → **frozen 冒烟**(对 dist 产物跑 `--smoke`)→ 完成
- 分发:别的机器遇 Gatekeeper 拦截 → `xattr -dr com.apple.quarantine dist/野兔v2.app`
- 体积 ~85M(主要 PyQt6 + Qt 库)

## 五、入口与自检体系(`main.py`)

| 模式 | 命令 | 内容 |
|---|---|---|
| GUI | `python3 main.py` | 正常启动 |
| 自检 | `--selftest` | 无界面:内置工具路径 / 面板注册表 / 当前设备 |
| 冒烟 | `--smoke` | 无头:助手起服务 → 请求 `/proxy`(校验页面标题)与 `/api/status`(校验 JSON)→ 停止,输出 `SMOKE_OK/FAIL` |
| 截图 | `--screenshot out.png` | offscreen 渲染窗口并截图(无显示环境/CI 用) |

`--smoke` 同时是**打包产物的验收标准**:`build.sh` 对 dist 里的二进制执行,
覆盖 PyInstaller 冻结路径(工具定位、页面资源读取、信号机制)。

## 六、质量保障(已执行的验证)

1. 助手功能测试(7 项):端口在线检测、Android/iPhone/未知 UA 分流、
   三种页面占位符零残留且含真实 IP、端口下线状态翻转 —— 全 PASS
2. GUI 生命周期:offscreen 驱动真实启停(启动 → ● 运行中+二维码+日志 →
   停止 → ○ 复位),逐张截图人工检查
3. `--selftest`/`--smoke` 源码态 + frozen 态双通过
4. qrterm 解码回归(zxing-cpp):全版本可解码,与官方库逐格一致
5. 稳定性规则:所有子线程回调经信号/队列回主线程;子进程统一 UTF-8+replace;
   服务关闭 `shutdown()+server_close()` 双保险且吞连接断开噪音

## 七、已知边界

- 无线调试(adb over Wi-Fi)暂未内置,当前走 USB
- 助手页面的复制按钮在个别老 WebView 上可能退化为「长按选择复制」(页面已提示)
- 端口在线探测无法区分具体抓包工具,只反映"端口是否有服务"
- Windows 产物需在 Windows 机器上打包(PyInstaller 不能跨平台),
  `野兔v2.spec` 已含 onefile 分支,命令:`pyinstaller 野兔v2.spec --noconfirm --clean`
